# 发布前检查表

这份清单用于审查，不自动发布、删除、强推或批量取消跟踪。

## 本地与远端身份

- [ ] 当前目录、Git 顶层目录、origin 和目标 GitHub 仓库一致。
- [ ] 已记录 HEAD、分支、工作树变更；保留用户未提交内容。
- [ ] 已核对远端默认分支/tip，避免用落后副本覆盖其他会话的提交。
- [ ] 用户授权覆盖本次项目和具体公开动作；独立私有依赖不自动视为已授权。

可用只读命令：

```sh
git rev-parse --show-toplevel
git status --short
git remote -v
git log -1 --oneline
git ls-files
git diff --cached --stat
git log --all --format= --name-only
```

先留意 remote URL 是否含凭据；不要把原始输出原样写进公开文档或 CI 日志。

## 文件与历史

- [ ] 私人 docs/config/日志/会话/运行证据已置于仓库外或精确 ignore 路径下。
- [ ] 用 `git check-ignore -v --no-index -- <path>` 验证规则，同时用 `git ls-files -- <path>` 检查是否仍受跟踪。
- [ ] 私人文件若已跟踪，只对已确认的精确路径执行 `git rm --cached -- <path>`，保留本地内容。
- [ ] 通用 README、安装文档、配置模板和许可证仍在公开范围。
- [ ] 当前源码与测试没有实际设备绑定、个人路径、会话 ID、私钥或 token。
- [ ] 允许保留的历史检查完成；没有仅因“可能有历史”而无根据地强制重写。
- [ ] 秘密匹配只输出文件名/类别，不输出秘密值；图片、压缩包和生成文件单独检查。

## 依赖与产物

- [ ] 安装脚本没有临时下载未声明的构建依赖；依赖及必要版本已声明。
- [ ] 完整功能需要的组件均可公开获取，或准确注明尚未开放的阻塞。
- [ ] 在干净目录按 README 的公开步骤运行成功，没有借用私有 `node_modules` 或作者部署。
- [ ] `npm pack --dry-run --json`（如适用）的文件清单已审查；注意该命令可能运行 lifecycle scripts，先审查包脚本。
- [ ] 实际包、release 附件和 source maps 不含私人资料；`.gitignore` 不替代包的 allowlist。
- [ ] GitHub issues/releases/wiki/Actions 等随可见性一起暴露的内容已按项目规模检查。

## 切换与回读

- [ ] 需要合并 public/private 项目时，有经过验证的仓库外离线备份，含 refs 及未提交/未跟踪资料。
- [ ] 唯一开发入口、origin、安装路径和文档链接已统一；不存在两套继续维护的实现。
- [ ] 原有运行配置、锁、恢复证据和私人文档被保留，不与源码一起清除。
- [ ] 改可见性/推送后独立读回仓库实际可见性、默认分支和提交。
- [ ] 删除旧仓库、重写历史或发布到包注册表分别具有明确授权。

报告应区分：源码整理完成、测试通过、远端已公开、独立安装验证、生产迁移完成。不要合并成一个未经证实的“全部完成”。
